# Latch 98 — Round 3 common rules

**Scope:** Latch 98 only. The Norn World Lab integrator independently decides what to research and change in Norn World Lab. Latch developers must NOT make Norn simulation plans or edit `apps/norn-world-lab/**`—not even its file adapter. Integration only receives a completed, tested Norn release from the other project.

**Baseline:** `Latch98-Round3-Shared-Base.zip`, identifier `LATCH-R3-2026-11-01`. All five workers start from these same exact source bytes, even if other threads finish early. **Do not rebase on a worker's patch**, touch another worker's files, or change the integrated baseline locally. Work in your own clone/copy.

**Deliver:** A ZIP named `Latch98-R3-Thread-X-Changes.zip` containing *only changed/new source files* at exact project-relative paths in your exclusive ownership. Include tests under your owned directory and a `CHANGES.md` there (or describe the full changelog in your response). No root-level standalone HTML, full project replacement, Git push, or regenerated whole-app HTML from another owner's code. If you want changes in a shared file, include an explicit `INTEGRATION_REQUEST.md` in the response, not as a patch file outside your ownership.

**Keep working:** Offline opening of standalone HTML, no mandatory CDN/account/network; 1998 Windows-like UI and Latch branding, setting in 2003; fullscreen Bloodline hides shell and has visible Return to Latch; separate windowed Bloodline shortcut; Postbox and Sprite Studio desktop icons; controller and touchscreen usability; save compatibility; all shipped games still playable.

**Protected first-run narrative:** On a fresh disk Norn World Lab is **NOT installed**. The player still must find the private October 15, 2003 Postbox message *“that program I told you about”*, obtain `NWLAB03.torrent`, download via SwarmWire, mount the virtual ISO, run `D:\Setup.exe`, and finish installation. Reopening the same browser save must remember the installation. Do not make Norn World Lab publicly available on PixelShelf or other websites, and do not create shortcuts that skip Setup.

**File and test quality:** No destructive save migration without explicit user opt-in and a backup path; protect user work on quota exhaustion and interrupted loads; no hard-coded credentials or signing keys; no proprietary game assets or copyrighted music without permission. Preserve baseline unit tests; write targeted tests and report exact commands run, pass/fail outcomes, and known gaps. Prefer working features and evidence, not decorative/placeholder controls.

**Ownership and merge:** `coordination/OWNERSHIP.json` is authoritative; owner IDs are `desktop`, `disk`, `apps`, `network`, `sprite`. You may inspect other files but cannot change them. Use `python tools/parallel_merge.py status` to inspect boundaries; test against untouched baseline using `python tools/parallel_merge.py check --thread YOUR_ID --zip YOUR_ZIP`. Never use `apply` on your only baseline. The Latch integrator handles merge conflicts and calls `python tools/release_check.py` after merging. `tools/`, `coordination/`, `src/`, root docs and release scripts belong to the integrator only.

**Norn import contract:** Your finished changes must work with the *unchanged frozen Norn app* in this baseline. The Norn integrator will later deliver its own full app/patch/tests; our Latch integrator alone updates the packaged Norn artifact, validates LatchFS integration, confirms no forced install bypass, and rebuilds standalone releases. No direct GitHub actions by workers.
